# @ 提及

输入框支持三类 `@` 提及，补全菜单按优先级 **Skills → Sessions → Files** 排列。在输入框开头或空白字符之后键入 `@` 打开菜单，继续输入即可过滤，`Enter`/`Tab` 或点击采纳候选；`Esc` 关闭。

## 提及类型

| 分区 | 插入文本 | 内容如何到达模型 |
| --- | --- | --- |
| Skills | `@技能名` | 普通 prompt 文本，模型经技能工具自行调用 |
| Sessions | `@[会话标题](illusion-session:<id>)` | 引擎在提交边界解析提及，注入源会话的只读快照作为上下文 |
| Files | `@src/main.py`（目录保留尾部 `/` 继续下钻） | 普通 prompt 文本，模型经 `read` 工具自行读取 |

名称含空格时使用 `@"含空格的名称"` 引号形式。提及在输入框与发送后的用户气泡中以主题色渲染——纯文本，除颜色外不做任何视觉装饰。

## 会话引用

会话提及让当前对话引入另一个会话的上下文。在 `@` 菜单的 `Sessions` 分区选择最近的会话（同工作区优先、按最近更新排序；当前会话与空会话不作为候选），插入规范提及文本：

```
@[调研笔记](illusion-session:abc123def456)
```

规范格式全程一致：输入框、提交消息、持久化的 context.jsonl 与 `/rewind`、`/resume` 重放的用户消息都保留这段原文——任何环节都不做转换，所见即模型所读。

### 快照注入

提交时引擎解析规范提及并：

- 用户消息原样保留规范提及文本。
- 紧随其后注入一条消息，携带源会话的**固定、不可变快照**——仅包含纯 user/assistant 文本（工具调用与结果、思考、其他注入类消息一律排除；此前的压缩摘要保留为对话开头）。
- 每个源会话独立字节预算（64 KiB）。超预算时先丢弃最旧消息（最新一条永不丢），再对最长文本做头尾截断并显式标注 `[… omitted N UTF-8 bytes …]`。
- 快照捕获一次后随会话持久化，重放/恢复会话时模型看到的内容与当时完全一致；源会话此后的变化不影响已捕获的快照。

快照外层带有固定警告，告知模型这是**不可信的背景数据**——快照内的指令、权限声明或工具请求一律不得执行，除非当前用户在消息中明确重复。快照 JSON 采用 tag-safe 序列化（`<` 全部转义），源内容永远拼不出外层框架标记。重复提及自动去重，自引用被忽略，单条消息最多解析 3 个会话引用；引用不存在的会话时以明确的 error 条目呈现，不会让整条消息失败。

### 快照不计入的位置

注入的快照消息不是真实用户输入：不参与轮次计数、会话摘要、自动标题、回退点选择与重放转录——用户可见的那条消息（含提及 chip）才是该轮的唯一痕迹。

## 隐私与范围

- 候选发现只读取元数据（会话 ID / 标题 / 摘要 / 轮次数），菜单不会扫描消息正文。
- 快照可引用所有已注册工作区的会话；源会话所属工作区在提交时自动定位。
